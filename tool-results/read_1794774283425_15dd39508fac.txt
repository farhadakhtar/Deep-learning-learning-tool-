   163→1. Introduction to Sequential Data and Recurrent Neural
   164→Networks
   165→
   166→1.1 What Is Sequential Data?
   167→     •    Sequential data is data in which order carries meaning — rearranging the elements changes (or
   168→          destroys) the meaning. This is different from ordinary tabular data, where the order of rows does
   169→          not matter.
   170→Common examples of sequential data:
   171→
   172→     •    Text / language — a sentence is a sequence of words; “dog bites man” ≠ “man bites dog”.
   173→     •    Speech / audio — a sequence of sound-pressure samples over time.
   174→     •    Time series — stock prices, weather readings, sensor logs: a sequence of numeric values indexed
   175→          by time.
   176→     •    Video — a sequence of image frames.
   177→     •    Biological sequences — DNA base pairs, protein amino-acid chains.
   178→Sequential data shares three properties that any model must respect:
   179→
   180→     •    It can be of variable length (sentences are not all the same number of words).
   181→     •    It is order-dependent (shuffling the elements changes the meaning).
   182→     •    It often has long-range dependencies — something at position 2 can affect the correct
   183→          interpretation of position 50.
   184→
   185→1.2 Why Feedforward Networks Struggle with Sequences
   186→A standard feedforward network (MLP) or a plain CNN expects one fixed-size input vector and produces
   187→one output, independently of any other input it has ever seen. This creates four concrete problems for
   188→sequence data:
   189→
   190→     •    Fixed input size. An MLP needs a fixed number of input features, but sentences and time series
   191→          vary in length.
   192→     •    No memory. Each input is processed in isolation; the network has no mechanism to “remember”
   193→          earlier inputs when processing the current one.
   194→     •    No parameter sharing across positions. If we tried to flatten a sequence into one long fixed
   195→          vector, the network would need separate weights for “word at position 5” versus “word at
   196→          position 50” — this does not generalise to lengths not seen in training and wastes parameters.
   197→     •    Violates the independence assumption. Standard supervised learning assumes examples are
   198→          independent; elements inside a sequence are, by definition, statistically dependent on their
   199→          neighbours.
   200→
   201→
   202→
   203→

   206→

   210→  Figure 1. A feedforward network has no memory; a recurrent network feeds its hidden state back into itself, carrying
   211→                                     information from one time step to the next.

   213→
   214→Key Insight
   215→A Recurrent Neural Network (RNN) fixes all four problems at once by introducing a hidden state that is
   216→updated at every time step using the same weights. This single idea — a feedback loop with shared
   217→parameters — is what allows one compact model to process sequences of any length.
   218→
   219→
   220→1.3 The Core Idea of a Recurrent Network
   221→      •   An RNN maintains a hidden state (also called the “context” or “memory”), denoted ht
   222→      •   At every time step t, the network reads the current input xt and combines it with the previous
   223→          hidden state ht−1 to produce a new hidden state ht.
   224→      •   The same weight matrices are reused at every time step (parameter sharing across time). This
   225→          is the single most important structural idea in this unit — it is what lets a fixed-size set of
   226→          parameters handle sequences of any length.
   227→      •   ht acts as a compressed summary of everything the network has read up to and including time t.
   228→      •   An output yt (a class label, a predicted next word, a predicted next value, etc.) can be produced
   229→          from ht at any time step where one is needed.
   230→                                     ht = f(xt, ht−1)   — general recurrence relation

   268→1.5 Applications of Recurrent Networks
   269→Because they can model dependencies across time, recurrent networks (and their gated variants, LSTM
   270→and GRU) have been used across a wide range of tasks:
   271→
   272→     •    Language modelling and text generation (predicting the next word/character).
   273→     •    Machine translation (sequence-to-sequence, encoder–decoder models).
   274→     •    Speech recognition (audio waveform → text).
   275→     •    Sentiment analysis and text classification.
   276→     •    Time-series forecasting — stock prices, electricity demand, weather.
   277→     •    Music and handwriting generation.
   278→     •    Video captioning and action recognition.
   279→     •    Chatbots and dialogue systems (largely superseded today by Transformers, but RNNs remain the
   280→          conceptual foundation and are still used in resource-constrained / streaming settings).

   291→2. Recurrent Neural Networks (RNN)
   292→
   293→2.1 Architecture
   294→     •    A simple (“vanilla”) RNN is a single cell that is applied repeatedly, once per time step, with the
   295→          same weights every time.
   296→     •    Drawing this repetition out explicitly over time steps is called unrolling the network — it turns
   297→          the recurrent (looped) picture into an ordinary, feedforward-looking computational graph that
   298→          we can apply standard backpropagation to.
   299→
   300→
   301→
   302→
   303→ Figure 2. An RNN drawn as a single folded cell (left) and unrolled across three time steps (right). Every column uses the
   304→                                      identical weight matrices Wxh, Whh, Why.
   305→
   306→     •    Zooming into a single time step shows exactly what happens inside the cell:
   307→
   308→
   309→
   310→

   316→

   318→                  transformed, summed with a bias, and squashed by tanh to produce the new hidden state.
   319→
   320→2.2 Forward-Pass Equations
   321→                                                     at = Wxh xt + Whh ht−1 + bh
   322→
   323→                                                           ht = tanh(at)
   324→
   325→                                                          yt = Why ht + by
   326→
   327→Significance of each term:
   328→
   329→     •     Wxh xt — brings in new information from the current input.
   330→     •     Whh ht−1 — brings forward everything remembered so far from the past.
   331→     •     tanh(·) — a nonlinearity that (a) lets the network represent non-linear relationships and (b)
   332→           squashes the state into (−1, 1), keeping it numerically bounded step after step.
   333→     •     Why ht + by — a read-out layer that turns the internal memory into whatever output the task
   334→           needs (a class score, a predicted value, next-word logits, …).
   335→
   336→2.3 Worked Example 1 — RNN Forward Pass, Step by Step
   337→Given
   338→Input sequence (T = 3, input size 2): x₁ = [1.0000, 0.5000], x₂ = [0.5000, -1.0000], x₃ = [-0.5000,
   339→1.0000]
   340→Initial hidden state: h₀ = [0.0000, 0.0000] (hidden size 2)
   341→Wxh = [[0.5000, -0.3000], [0.2000, 0.4000]], Whh = [[0.1000, 0.4000], [-0.2000, 0.3000]], bh =
   342→[0.1000, -0.1000]
   343→Why = [[0.6000, -0.3000], [0.2000, 0.5000]], by = [0.1000, 0.2000]
   344→
   345→
   346→Dr. Manoj Kumar Sharma — Manipal University Jaipur                                                               Page 9 of 41
   347→CCE3144 – Deep Learning                                                                 Unit: Recurrent Neural Networks
   348→
   349→
   350→
   351→Step 1 — Compute h₁ (process the first input)
   352→We need a1 = Wxh x1 + Whh h0 + bh. Since h0 = [0.0000, 0.0000], the recurrent term contributes nothing yet
   353→— this is the very first step, so there is no history to bring forward.
   354→Wxh x₁ = (0.5×1.0 + (−0.3)×0.5, 0.2×1.0 + 0.4×0.5) = (0.35, 0.40)
   355→
   356→a₁ = (0.35, 0.40) + (0, 0) + (0.1, −0.1) = [0.4500, 0.3000]
   357→
   358→h₁ = tanh([0.4500, 0.3000]) = [0.4219, 0.2913]
   359→
   360→Why this step matters
   361→tanh squashes each pre-activation into (−1, 1). Both components of a₁ were modest in size, so tanh has
   362→not saturated — the gradient through this step will still be healthy (we revisit this idea in Section 2.7).
   363→
   364→Step 2 — Compute h₂ (now the recurrence is active)
   365→Wxh x₂ = (0.5×0.5 + (−0.3)×(−1.0), 0.2×0.5 + 0.4×(−1.0)) = (0.5500, −0.3000)
   366→
   367→Whh h₁ = (0.1×0.4219 + 0.4×0.2913, −0.2×0.4219 + 0.3×0.2913) = (0.1587, 0.0030)
   368→
   369→a₂ = (0.5500, −0.3000) + (0.1587, 0.0030) + (0.1, −0.1) = [0.8087, -0.3970]
   370→
   371→h₂ = tanh([0.8087, -0.3970]) = [0.6689, -0.3774]
   372→
   373→     •    Notice that h₂ depends on x₂ and on h₁ (which itself depended on x₁). This is exactly how the RNN
   374→          carries information forward — h₂ already contains a trace of x₁.
   375→
   376→Step 3 — Compute h₃
   377→Wxh x₃ = (−0.5500, 0.3000),            Whh h₂ = (−0.0841, −0.2470)
   378→
   379→a₃ = [-0.5341, -0.0470]         ⇒      h₃ = tanh([-0.5341, -0.0470]) = [-0.4885, -0.0470]
   380→
   381→Step 4 — Produce the output y₃
   382→y₃ = Why h₃ + by = [[0.6000, -0.3000], [0.2000, 0.5000]] × [-0.4885, -0.0470] + [0.1000, 0.2000] = [-0.1790,
   383→0.0788]
   384→
   385→     •    This is a many-to-one read-out: we only needed an output at the final time step (e.g. classifying
   386→          the whole sequence). If a prediction were needed at every step, the same Why, by read-out
   387→          would be applied to h₁ and h₂ as well.

   408→2.4 Types of RNN Architectures
   409→The recurrence itself never changes; what changes from application to application is simply where inputs
   410→enter and where outputs are read out.
   411→
   412→
   413→
   414→
   415→                  Figure 4. Five standard input/output wiring patterns built from the same recurrent cell.
   416→
   417→     •    One-to-one — a single input maps to a single output; degenerates to a normal feedforward layer
   418→          (rarely used with recurrence, shown for completeness).
   419→     •    One-to-many — one input, a whole output sequence (e.g. image captioning: one image → a
   420→          sentence).
   421→     •    Many-to-one — a whole input sequence, one output (e.g. sentiment classification) — this is the
   422→          pattern used in Worked Example 1 above.
   423→     •    Many-to-many (aligned) — one output per input, same length (e.g. part-of-speech tagging).
   424→     •    Many-to-many (encoder–decoder) — an encoder RNN compresses the input into a context
   425→          vector; a separate decoder RNN generates the (possibly different-length) output sequence from
   426→          it (e.g. machine translation).
   427→
   428→2.5 Training an RNN: Backpropagation Through Time (BPTT)
   429→     •    Idea: unroll the RNN for all T time steps (as in Figure 2), which turns it into one large feedforward
   430→          computational graph — then apply ordinary backpropagation to that graph.
   431→     •    Because the same weight matrix (say Whh) is reused at every time step, its total gradient is the
   432→          sum of the gradient contributed at every time step:
   433→                                              ∂L/∂Whh = Σₜ₌₁ᵀ ∂L/∂at ⊗ ht−1
   434→
   435→
   436→Dr. Manoj Kumar Sharma — Manipal University Jaipur                                                           Page 11 of 41
   437→CCE3144 – Deep Learning                                                               Unit: Recurrent Neural Networks
   438→
   439→
   440→
   441→     •    Each backward step from ht to ht−1 multiplies the incoming gradient by Whhᵀ and by the local tanh
   442→          derivative — this repeated multiplication is the root cause of the vanishing/exploding gradient
   443→          problem (Section 2.7).
   444→
   445→
   446→
   447→
   448→Figure 5. BPTT: the loss gradient flows backward through every copy of the network, moving from h3 back to h2, h1 and
   449→                                                          h0.

   451→2.6 Worked Example 2 — BPTT Gradient Computation
   452→Given
   453→Continue Worked Example 1. A target output target₃ = [1.0000, 0.0000] is supplied (one-hot encoding
   454→for class 0), and the squared-error loss is applied at the final time step only (a many-to-one setup):
   455→
   456→                 L = ½ ‖ y₃ − target₃ ‖² = ½ ‖ [-0.1790, 0.0788] − [1.0000, 0.0000] ‖² = 0.6981
   457→
   458→Step 1 — Gradient at the output
   459→∂L/∂y₃ = y₃ − target₃ = [-0.1790, 0.0788] − [1.0000, 0.0000] = [-1.1790, 0.0788]
   460→
   461→     •    For squared error, ∂L/∂y = predicted − target — the gradient simply points from the prediction
   462→          toward the target, scaled by the error.
   463→
   464→Step 2 — Backprop into h₃ through the output layer
   465→∂L/∂h₃ = Whyᵀ ∂L/∂y₃ = [[0.6000, -0.3000], [0.2000, 0.5000]]ᵀ × [-1.1790, 0.0788] = [-0.6916, 0.3931]
   466→
   467→Step 3 — Backprop through tanh at t = 3
   468→     •    The derivative of tanh is 1 − tanh²(a) = 1 − h², evaluated using the already-computed forward-
   469→          pass value — this is why we saved every h_t during the forward pass.
   470→∂L/∂a₃ = ∂L/∂h₃ ⊙ (1 − h₃²) = [-0.6916, 0.3931] ⊙ (1 − [-0.4885, -0.0470]²) = [-0.5266, 0.3922]
   471→
   472→
   473→
   474→
   475→Dr. Manoj Kumar Sharma — Manipal University Jaipur                                                      Page 12 of 41
   476→CCE3144 – Deep Learning                                                           Unit: Recurrent Neural Networks
   477→
   478→
   479→
   480→Step 4 — Gradient contribution to Whh from t = 3
   481→∂L/∂Whh |₃ = ∂L/∂a₃ ⊗ h₂ = [-0.5266, 0.3922] ⊗ [0.6689, -0.3774] = [[-0.3522, 0.1987], [0.2624, -
   482→0.1480]]
   483→
   484→     •    “⊗” here is an outer product: a gradient vector combined with the hidden state that was
   485→          multiplied by Whh on the forward pass — this is the standard rule for the gradient of a matrix
   486→          multiplication.

   502→The contribution at t = 1 is multiplied by h₀ = (0, 0), the initial hidden state. With a zero initial state

   504→vanishes.

   506→∂L/∂h₁ itself is still non-zero, so it correctly continues to update Wxh and bh through this step.

   518→2.7 The Vanishing and Exploding Gradient Problem
   519→     •    Look again at Steps 5–6 above: every step back multiplies the gradient by Whhᵀ and by a tanh-
   520→          derivative factor that is always ≤ 1.
   521→     •    Over T time steps this becomes roughly a product of T such factors — informally, gradient ∝ λᵀ,
   522→          where λ reflects the typical size of Whhᵀ × tanh′.
   523→     •    If λ < 1: the product shrinks exponentially with T — the vanishing gradient problem. Early time
   524→          steps receive a near-zero learning signal, so the network effectively cannot learn long-range
   525→          dependencies.

   578→3. Long Short-Term Memory (LSTM)
   579→
   580→3.1 Motivation
   581→     •    Plain RNNs struggle to learn long-range dependencies because gradients shrink (or blow up)
   582→          exponentially as they are backpropagated through many time steps (Section 2.7).
   583→     •    LSTM (Hochreiter & Schmidhuber, 1997) fixes this by giving the network a separate memory
   584→          channel — the cell state — that information can flow along with only minor, mostly linear
   585→          changes, instead of being repeatedly squashed through a matrix multiply and a tanh at every
   586→          step.
   587→     •    Three gates (small neural networks with sigmoid outputs in (0, 1)) learn when to write to, erase
   588→          from, and read from this memory.
   589→
   590→3.2 Architecture
   591→     •    Cell state Ct — the long-term memory “conveyor belt” running along the top of the diagram
   592→          below.
   593→     •    Forget gate ft — decides what fraction of the old cell state to keep.
   594→     •    Input gate it — decides how much of the new candidate information to write in.
   595→     •    Candidate c̃t — the new content proposed for the cell state (not yet gated).
   596→     •    Output gate ot — decides how much of the (updated) cell state to expose as the hidden state /
   597→          output.
   598→
   599→

   609→                                     this is what protects the gradient from vanishing.

   611→3.3 Equations
   612→All four gates/candidates first form the same concatenated input, then apply their own weights:
   613→
   614→                    zₜ = [ hₜ₋₁ ; xₜ ]    (concatenate previous hidden state and current input)
   615→
   616→                                                        ft = σ(Wf zₜ + bf)
   617→
   618→                                                        it = σ(Wi zₜ + bi)
   619→
   620→                                                      c̃t = tanh(Wc zₜ + bc)
   621→
   622→                                                     Ct = ft ⊙ Ct−1 + it ⊙ c̃t
   623→
   624→                                                       ot = σ(Wo zₜ + bo)
   625→
   626→                                                       ht = ot ⊙ tanh(Ct)
   627→
   628→Significance of each equation:
   629→
   630→     •    Forget gate — a sigmoid output near 0 erases that part of memory; near 1 preserves it
   631→          completely.
   632→     •    Input gate × candidate — the network only writes new information where the input gate allows
   633→          it, protecting unrelated parts of memory.
   634→
   635→
   636→
   637→

   639→CCE3144 – Deep Learning                                                                  Unit: Recurrent Neural Networks
   640→
   641→
   642→
   643→     •    Cell-state update — additive and element-wise (no matrix multiply, no squashing) — this is the
   644→          key structural difference from a plain RNN, and is what allows gradients to flow across many steps
   645→          largely unchanged (Section 3.5).
   646→     •    Output gate — the cell can hold information in Ct without necessarily exposing it in ht — memory
   647→          and “what to output right now” are decoupled.

   712→3.5 Why LSTM Solves the Vanishing Gradient Problem
   713→     •    Recall from Section 2.7 that a plain RNN's gradient must pass through a matrix multiply by Whh
   714→          and a tanh derivative at every single step — repeated many times, this shrinks (or explodes)
   715→          exponentially.
   716→     •    The LSTM cell-state recurrence is Ct = ft ⊙ Ct−1 + (new term) — this is additive, so ∂Ct/∂Ct−1 = ft
   717→          (an element-wise scaling, not a matrix multiply followed by a squashing nonlinearity).
   718→     •    If the forget gate learns to stay close to 1 for information that should be remembered, the
   719→          gradient can flow backward through many time steps with almost no shrinkage — an unimpeded
   720→          “gradient highway” along the cell state.
   721→     •    This does not eliminate vanishing gradients entirely (very long sequences can still be difficult, and
   722→          the hidden-state path through tanh still exists), but it dramatically extends how far back an RNN-
   723→          family model can learn useful dependencies — this is the single biggest reason LSTMs outperform
   724→          plain RNNs in practice.
   725→
   726→3.6 Advantages and Limitations
   727→     •    Advantages: learns long-range dependencies far better than a plain RNN; the gating mechanism
   728→          is learned end-to-end from data; remains a strong, well-understood baseline for sequence tasks.
   729→     •    Limitations: four sets of weights (forget, input, candidate, output) means roughly 4× the
   730→          parameters of a plain RNN of the same hidden size (Section 6); inherently sequential computation
   731→          makes it slower to train than fully parallel architectures such as Transformers; still not immune
   732→          to very long sequences (hundreds/thousands of steps).

   743→4. Gated Recurrent Unit (GRU)
   744→
   745→4.1 Motivation
   746→     •    Introduced by Cho et al. (2014), the GRU asks: can we get most of the benefit of LSTM's gating —
   747→          protection against vanishing gradients, learned control over memory — with a simpler cell?
   748→     •    GRU merges the forget and input gates into a single update gate, and removes the separate cell
   749→          state entirely — the hidden state itself carries long-term memory.
   750→     •    Fewer gates means fewer parameters (Section 6) and typically faster training, while remaining
   751→          competitive with LSTM on many tasks.
   752→
   753→4.2 Architecture
   754→     •    Update gate zt — decides how much of the old hidden state to keep versus how much of the new
   755→          candidate to mix in. It plays the combined role of LSTM's forget and input gates.
   756→     •    Reset gate rt — decides how much of the past hidden state to use when forming the new
   757→          candidate content.
   758→     •    Candidate hidden state h̃t — a proposed new hidden-state value, computed using the reset
   759→          (partially forgotten) past state.
   760→     •    No separate cell state — ht itself is the blend of old and new content.
   761→
   762→
   763→

   766→                                   candidate, controlled entirely by the update gate zt.

   778→                    zₜ = [ hₜ₋₁ ; xₜ ]    (concatenate previous hidden state and current input)
   779→
   780→                                                      zt = σ(Wz zₜ + bz)
   781→
   782→                                                       rt = σ(Wr zₜ + br)
   783→
   784→                                             h̃t = tanh(Wh [ rt ⊙ ht−1 ; xt ] + bh)
   785→
   786→                                                ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t
   787→
   788→Significance of each equation:
   789→
   790→     •    Update gate — close to 0 keeps the old state almost unchanged; close to 1 replaces it almost
   791→          entirely with the new candidate.
   792→     •    Reset gate — close to 0 makes the candidate ignore the past and depend mostly on the current
   793→          input (useful when starting a new, unrelated chunk of a sequence, e.g. a new sentence).
   794→     •    Final blend — a convex combination (weights sum to 1) of old state and new candidate. Like the
   795→          LSTM cell-state update, this blend is dominated by simple arithmetic rather than repeated matrix
   796→          multiplication, which is what protects the gradient.

   856→4.5 GRU vs LSTM
   857→     •    GRU has no output gate — the full hidden state is always exposed (LSTM can hide part of its cell

   860→          design but gives slightly less representational flexibility.
   861→     •    GRU uses one combined update gate where LSTM uses two independent gates (forget, input) —
   862→          fewer parameters, slightly less fine-grained control.
   863→     •    In practice, the two perform comparably on many tasks; GRU is often preferred when training
   864→          speed / parameter budget matters, LSTM when maximum modelling flexibility is preferred. Both
   865→          comfortably outperform a plain RNN on long sequences.

   876→5. Recurrent Neural Network Language Models
   877→
   878→5.1 What Is a Language Model?
   879→     •    A language model assigns a probability to sequences of words, or equivalently, predicts a
   880→          probability distribution over the next word given all the words seen so far.
   881→     •    Formally, for a sequence of words w1, …, wT, a language model estimates:
   882→                     P(w₁, …, wᵀ) = P(w₁) · P(w₂ | w₁) · P(w₃ | w₁, w₂) · ⋯ · P(wᵀ | w₁, …, wᵀ₋₁)
   883→
   884→     •    Language models power autocomplete, text generation, machine translation (as the decoder),
   885→          speech recognition (choosing the most fluent transcription), and are the training objective
   886→          behind today's large language models.
   887→
   888→5.2 An RNN as a Language Model — Architecture
   889→     •    Step 1 — Embedding: each word is converted from a discrete token into a dense vector (a row
   890→          of a learned embedding matrix E).
   891→     •    Step 2 — Recurrence: the embedding is fed into the RNN (or LSTM / GRU) exactly as in Sections
   892→          2–4; the hidden state accumulates context from every word seen so far.
   893→     •    Step 3 — Read-out: at every time step, the hidden state is projected to a vector of logits, one per
   894→          vocabulary word, and passed through softmax to obtain a probability distribution over the next
   895→          word.
   896→     •    Training: at each step, the true next word is compared against the predicted distribution using
   897→          cross-entropy loss; the same shared weights are updated via BPTT, exactly as in Section 2.5.
   898→

   987→          average cross-entropy loss back onto an intuitive scale:
   988→                     Average loss = (L₁ + L₂ + ⋯) / T           Perplexity = exp(Average loss)

  1006→          best); perplexity equal to the vocabulary size corresponds to uniform random guessing (the
  1007→          practical worst case for a sensible model).

  1009→5.6 Beyond the Basics
  1010→     •    Teacher forcing — during training, the true previous word is fed as input at every step (as in
  1011→          Worked Example 5), even if the model's own previous prediction was wrong; this stabilises and
  1012→          speeds up training.
  1013→     •    Generation / sampling — at inference time there is no “true” next word, so the model's own
  1014→          output is fed back as the next input. Common strategies: greedy decoding (always pick the
  1015→          highest-probability word), sampling with temperature, and beam search.
  1016→     •    LSTM / GRU language models — in practice, the plain-RNN recurrence in this section is almost
  1017→          always replaced by an LSTM or GRU cell (Sections 3–4), since long documents need the improved
  1018→          long-range memory.
  1019→     •    Modern context — Transformer-based language models have largely superseded RNN-based
  1020→          ones for state-of-the-art results, but the evaluation concepts introduced here — next-word
  1021→          prediction, cross-entropy loss, and perplexity — remain exactly the same and are used to evaluate
  1022→          Transformer language models too.

  1125→Q1. Which of the following is NOT a defining property of sequential data? [1 mark]
  1126→     (A) Every sequence in the dataset must have exactly the same length. ✓ correct
  1127→     (B) The order of elements affects the meaning.
  1128→     (C) Later elements can depend on much earlier elements.
  1129→     (D) Elements are not statistically independent of their neighbours.
  1130→Answer: (A)
  1131→Solution:
  1132→Sequential data is explicitly allowed to be of variable length — sentences, audio clips and time series
  1133→routinely differ in length. This variability is precisely why ordinary feedforward networks (which need a
  1134→fixed-size input) struggle with sequences (Section 1.2), and why RNNs, which process one element at a
  1135→time and share weights across positions, are needed. Options B, C, and D all describe real properties of
  1136→sequential data (Section 1.1).

  1138→Q2. What is the single most important structural idea that lets an RNN process sequences of any length
  1139→using a fixed number of parameters? [1 mark]
  1140→     (A) Using convolutional filters that slide over the input.
  1141→     (B) Increasing the hidden size whenever the sequence is longer.
  1142→     (C) Sharing the same weight matrices across all time steps. ✓ correct
  1143→     (D) Training a separate small network for every time step.
  1144→Answer: (C)
  1145→Solution:
  1146→Because Wxh, Whh, Why (and their biases) are reused, identically, at every time step, the total number
  1147→of parameters does not grow with sequence length — a 5-word sentence and a 500-word document are
  1148→processed by exactly the same set of weights, applied repeatedly (Section 1.3, Section 2.1). Option D is
  1149→effectively the opposite of parameter sharing and would not generalise to unseen lengths.

  1169→Q4. If a pre-activation value a = 0, what are tanh(a) and its local derivative 1 − tanh²(a) at that point? [1
  1170→mark]

  1172→     (B) 1 and 0

  1175→Answer: (D)
  1176→Solution:
  1177→tanh(0) = 0, and 1 − tanh²(0) = 1 − 0 = 1. This is the largest possible value the tanh-derivative factor can

  1182→Q5. In BPTT for a plain RNN, the total gradient of the loss with respect to Whh is obtained by: [1 mark]
  1183→     (A) Summing the gradient contributions from every time step. ✓ correct

  1193→Q6. The vanishing gradient problem in plain RNNs is primarily caused by: [1 mark]
  1194→     (A) Using too few hidden units.
  1195→     (B) Using too large a learning rate.
  1196→     (C) The softmax function saturating.
  1197→     (D) Repeated multiplication by Whhᵀ and a tanh-derivative factor (≤ 1) at every backward step. ✓
  1198→     correct
  1199→Answer: (D)
  1200→Solution:
  1201→Backpropagating through T time steps multiplies the gradient by roughly T copies of Whhᵀ and a tanh-
  1202→derivative factor. If the typical size of this product (informally λ) is less than 1, the gradient shrinks
  1203→exponentially with T (Section 2.7, Figure 6). This has nothing to do with learning rate (B) or softmax (C),
  1204→and too few hidden units (A) is a capacity problem, not a gradient-flow problem.

  1331→Part B — Descriptive and Numerical Questions (Q16–Q50)
  1332→Q16. List and briefly explain three properties that any model of sequential data must respect. [3 marks]
  1333→Solution:
  1334→     •    Variable length — sequences in a dataset are rarely all the same length (sentences, audio clips,
  1335→          etc.), so the model cannot assume a fixed-size input.
  1336→     •    Order-dependence — shuffling the elements changes (or destroys) the meaning; e.g. “dog bites
  1337→          man” ≠ “man bites dog”.
  1338→     •    Long-range dependencies — information at one position can affect the correct interpretation of
  1339→          a position much later in the sequence, so the model needs some form of memory (Section 1.1).
  1340→
  1341→Q17. Give two distinct reasons why a plain feedforward network (MLP) with a flattened input vector is
  1342→a poor choice for variable-length text classification. [2 marks]
  1343→Solution:
  1344→     •    Fixed input size: an MLP requires a predetermined number of input features. Flattening text of
  1345→          different lengths into one vector either forces truncation/padding to an arbitrary maximum
  1346→          length, or simply cannot be done consistently.
  1347→     •    No parameter sharing across positions: if position 5 and position 50 of the flattened vector each
  1348→          get their own weights, the network must separately learn what a given word means at every
  1349→          possible position, wasting parameters and failing to generalise to lengths/positions not seen

  1439→Q24. Derive an expression for the Jacobian ∂ht/∂ht−1 of a plain RNN, and explain its role in BPTT. [4
  1440→marks]
  1441→Solution:
  1442→Step 1 — Write the recurrence: hₜ = tanh(aₜ), where aₜ = Wxh xₜ + Whh hₜ₋₁ + bh
  1443→Step 2 — Differentiate aₜ with respect to hₜ₋₁: ∂aₜ/∂hₜ₋₁ = Whh (the only term in aₜ that depends on hₜ₋₁)
  1444→Step 3 — Apply the chain rule through tanh: ∂hₜ/∂hₜ₋₁ = diag(1 − hₜ²) · Whh
  1445→     •    Here diag(1−hₜ²) is a diagonal matrix of the elementwise tanh-derivative values.
  1446→
  1447→Role in BPTT
  1448→This single-step Jacobian is exactly the factor that gets multiplied in, once per time step, when the
  1449→gradient is propagated backward from hₜ to hₜ₋₁ (Steps 5–6 of Worked Example 2). Its repeated
  1450→application — diag(1−h²)·Whh chained T times — is precisely the mechanism behind the
  1451→vanishing/exploding gradient problem of Section 2.7: if the dominant eigenvalue of this product has
  1452→magnitude < 1, gradients vanish; if > 1, they explode.
  1453→
  1454→Q25. Explain why the tanh derivative being maximised at a = 0 is relevant to the vanishing gradient
  1455→problem. [2 marks]
  1456→Solution:
  1457→     •    1 − tanh²(a) reaches its maximum value of 1 exactly at a = 0, and falls toward 0 as |a| grows (tanh
  1458→          saturates near ±1).
  1459→     •    Since each backward step through tanh multiplies the gradient by this factor, the best possible
  1460→          case at any single step is a multiplier of exactly 1 (no shrinkage) — it can never exceed 1. In
  1461→          practice, hidden units are rarely sitting at exactly a = 0, so the realistic per-step factor is usually
  1462→          noticeably below 1, which compounds multiplicatively over many time steps into the vanishing
  1463→          gradient problem (Section 2.7, and Q4 of Part A).

  1485→Q27. Explain the difference between the vanishing and exploding gradient problems in terms of the
  1486→quantity λ introduced in Section 2.7. [2 marks]
  1487→Solution:
  1488→     •    λ informally represents the typical magnitude of Whhᵀ combined with the local tanh-derivative
  1489→          factor, applied once per backward time step.

  1491→          gradient problem; early time steps get almost no learning signal.

  1493→          training destabilises. λ = 1 is the (unstable) knife-edge boundary between the two regimes.

  1504→Q29. List three standard mitigations for vanishing/exploding gradients in RNNs, and explain one of
  1505→them in detail. [3 marks]
  1506→Solution:
  1507→     •    Gradient clipping, careful (e.g. orthogonal) weight initialisation, truncated BPTT, and gated
  1508→          architectures (LSTM/GRU) are all standard mitigations (Section 2.7).
  1509→     •    Gradient clipping in detail: after computing the gradient for a batch, its norm ‖g‖ is compared
  1510→          against a threshold τ. If ‖g‖ > τ, the gradient is rescaled: g ← g × (τ/‖g‖), which preserves its
  1511→          direction but caps its magnitude. This is cheap to compute, requires no architecture change, and
  1512→          directly prevents the huge, destabilising updates caused by exploding gradients — though it does
  1513→          nothing to fix vanishing gradients.

  1574→Q34. Explain, using the forget-gate mechanism, why an LSTM can in principle remember information
  1575→for 100+ time steps, while a plain RNN struggles to. [3 marks]
  1576→Solution:
  1577→     •    If the forget gate learns a value close to 1 for a particular memory component, that component
  1578→          of the cell state is carried forward with almost no attenuation at every step: Ct = 1 × Ct−1 +
  1579→          (small/zero new term) ≈ Ct−1.
  1580→     •    Because this update is additive and element-wise (Section 3.5), the corresponding backward
  1581→          gradient ∂Ct/∂Ct−1 = ft ≈ 1 as well — so information (and its gradient) can survive many steps
  1582→          unchanged, in principle indefinitely.
  1583→     •    A plain RNN has no such mechanism: its hidden state is fully overwritten by tanh(…) at every step,
  1584→          and the corresponding gradient is repeatedly multiplied by Whhᵀ and a tanh-derivative < 1, which
  1585→          compounds toward zero (Section 2.7) — there is no learned way to “protect” a piece of
  1586→          information from this decay.

  1683→     •    In practice zt learns intermediate values, blending the two continuously depending on the input.

  1695→Q45. Write the chain-rule factorisation of P(w₁, …, wᵀ) used by a language model, and explain in words
  1696→what each factor represents. [3 marks]
  1697→Solution:
  1698→                          P(w₁, …, wᵀ) = P(w₁) · P(w₂|w₁) · P(w₃|w₁,w₂) · ⋯ · P(wᵀ|w₁,…,wᵀ₋₁)
  1699→
  1700→     •    This is simply the probability chain rule applied to a sequence: the joint probability of the whole
  1701→          sequence equals the product of each word's probability conditioned on every word before it.
  1702→     •    An RNN language model approximates every conditional factor P(wₜ | w₁,…,wₜ₋₁) with a single
  1703→          softmax output at step t, whose entire dependence on the (arbitrarily long) history w₁,…,wₜ₋₁ is
  1704→          compressed into the fixed-size hidden state hₜ₋₁ (Section 5.1–5.2).

  1715→log(0.5202) = 0.6535

  1735→Q48. Explain teacher forcing and describe one problem it can cause at inference (generation) time. [3
  1736→marks]
  1737→Solution:
  1738→     •    Teacher forcing: during training, the model is always fed the true previous word as input at each
  1739→          step, regardless of what the model itself would have predicted (Section 5.6).
  1740→     •    Problem — exposure bias: at generation time there is no ground truth to feed back in, so the
  1741→          model must feed in its own (possibly imperfect) previous prediction. Since the model never
  1742→          practised recovering from its own mistakes during training, small errors can compound as
  1743→          generation proceeds, leading to increasingly poor output quality — a mismatch between the
  1744→          training and inference conditions.

  1746→Q49. Give one application example each for plain RNN, LSTM, and GRU, and briefly justify each choice.
  1747→[3 marks]
  1748→Solution:
  1749→     •    Plain RNN: a short, fixed-pattern signal classifier (e.g. detecting a simple gesture from a few
  1750→          dozen accelerometer readings) — the sequences are short enough that vanishing gradients are
  1751→          not a serious concern, so the simplicity and speed of a plain RNN is an acceptable trade-off.
  1752→     •    LSTM: long-document sentiment analysis or long-range time-series forecasting (e.g. multi-week
  1753→          demand forecasting) — the long-range memory and fine-grained gating are worth the extra
  1754→          parameters when dependencies span long distances.
  1755→     •    GRU: on-device / mobile keyboard next-word prediction — a tight compute and memory budget
  1756→          favours GRU's roughly 25% parameter saving over LSTM, while still comfortably outperforming a
  1757→          plain RNN.

  1759→Q50. Summarise, in a short set of bullet points, the historical progression from RNN → LSTM → GRU →
  1760→Transformer, giving the main motivation behind each step. [4 marks]
  1761→Solution:
  1762→     •    RNN: introduced parameter sharing across time via a recurrent hidden state, solving the fixed-
  1763→          input-size and no-memory problems of feedforward networks (Section 1–2).
  1764→     •    → LSTM: added gated, additive memory (the cell state) specifically to fix the vanishing gradient
  1765→          problem that crippled plain RNNs on long sequences (Section 2.7 → Section 3).
  1766→     •    → GRU: simplified LSTM's gating (2 gates instead of 3, no separate cell state) to reduce
  1767→          parameters and training cost while keeping most of the long-range-memory benefit (Section 4).
  1768→     •    → Transformer (beyond this unit): replaced recurrence entirely with self-attention, allowing
  1769→          every position to directly attend to every other position. This removes the sequential step-by-
  1770→          step bottleneck (enabling full parallelisation across time during training) and provides a more
  1771→          direct path for gradients/information between distant positions than even LSTM/GRU can offer.
