1. Introduction to Sequential Data and Recurrent Neural
Networks

1.1 What Is Sequential Data?
     •    Sequential data is data in which order carries meaning — rearranging the elements changes (or
          destroys) the meaning. This is different from ordinary tabular data, where the order of rows does
          not matter.
Common examples of sequential data:

     •    Text / language — a sentence is a sequence of words; “dog bites man” ≠ “man bites dog”.
     •    Speech / audio — a sequence of sound-pressure samples over time.
     •    Time series — stock prices, weather readings, sensor logs: a sequence of numeric values indexed
          by time.
     •    Video — a sequence of image frames.
     •    Biological sequences — DNA base pairs, protein amino-acid chains.
Sequential data shares three properties that any model must respect:

     •    It can be of variable length (sentences are not all the same number of words).
     •    It is order-dependent (shuffling the elements changes the meaning).
     •    It often has long-range dependencies — something at position 2 can affect the correct
          interpretation of position 50.

1.2 Why Feedforward Networks Struggle with Sequences
A standard feedforward network (MLP) or a plain CNN expects one fixed-size input vector and produces
one output, independently of any other input it has ever seen. This creates four concrete problems for
sequence data:

     •    Fixed input size. An MLP needs a fixed number of input features, but sentences and time series
          vary in length.
     •    No memory. Each input is processed in isolation; the network has no mechanism to “remember”
          earlier inputs when processing the current one.
     •    No parameter sharing across positions. If we tried to flatten a sequence into one long fixed
          vector, the network would need separate weights for “word at position 5” versus “word at
          position 50” — this does not generalise to lengths not seen in training and wastes parameters.
     •    Violates the independence assumption. Standard supervised learning assumes examples are
          independent; elements inside a sequence are, by definition, statistically dependent on their
          neighbours.

Key Insight
A Recurrent Neural Network (RNN) fixes all four problems at once by introducing a hidden state that is
updated at every time step using the same weights. This single idea — a feedback loop with shared
parameters — is what allows one compact model to process sequences of any length.


1.3 The Core Idea of a Recurrent Network
      •   An RNN maintains a hidden state (also called the “context” or “memory”), denoted ht
      •   At every time step t, the network reads the current input xt and combines it with the previous
          hidden state ht−1 to produce a new hidden state ht.
      •   The same weight matrices are reused at every time step (parameter sharing across time). This
          is the single most important structural idea in this unit — it is what lets a fixed-size set of
          parameters handle sequences of any length.
      •   ht acts as a compressed summary of everything the network has read up to and including time t.
      •   An output yt (a class label, a predicted next word, a predicted next value, etc.) can be produced
          from ht at any time step where one is needed.
                                     ht = f(xt, ht−1)   — general recurrence relation

1.5 Applications of Recurrent Networks
Because they can model dependencies across time, recurrent networks (and their gated variants, LSTM
and GRU) have been used across a wide range of tasks:

     •    Language modelling and text generation (predicting the next word/character).
     •    Machine translation (sequence-to-sequence, encoder–decoder models).
     •    Speech recognition (audio waveform → text).
     •    Sentiment analysis and text classification.
     •    Time-series forecasting — stock prices, electricity demand, weather.
     •    Music and handwriting generation.
     •    Video captioning and action recognition.
     •    Chatbots and dialogue systems (largely superseded today by Transformers, but RNNs remain the
          conceptual foundation and are still used in resource-constrained / streaming settings).

2. Recurrent Neural Networks (RNN)

2.1 Architecture
     •    A simple (“vanilla”) RNN is a single cell that is applied repeatedly, once per time step, with the
          same weights every time.
     •    Drawing this repetition out explicitly over time steps is called unrolling the network — it turns
          the recurrent (looped) picture into an ordinary, feedforward-looking computational graph that
          we can apply standard backpropagation to.




 Figure 2. An RNN drawn as a single folded cell (left) and unrolled across three time steps (right). Every column uses the
                                      identical weight matrices Wxh, Whh, Why.

     •    Zooming into a single time step shows exactly what happens inside the cell:

         Figure 3. Inside one RNN cell at time step t: the previous hidden state and the current input are each linearly

2.2 Forward-Pass Equations
                                                     at = Wxh xt + Whh ht−1 + bh

                                                           ht = tanh(at)

                                                          yt = Why ht + by

Significance of each term:

     •     Wxh xt — brings in new information from the current input.
     •     Whh ht−1 — brings forward everything remembered so far from the past.
     •     tanh(·) — a nonlinearity that (a) lets the network represent non-linear relationships and (b)
           squashes the state into (−1, 1), keeping it numerically bounded step after step.
     •     Why ht + by — a read-out layer that turns the internal memory into whatever output the task
           needs (a class score, a predicted value, next-word logits, …).

2.3 Worked Example 1 — RNN Forward Pass, Step by Step
Given
Input sequence (T = 3, input size 2): x₁ = [1.0000, 0.5000], x₂ = [0.5000, -1.0000], x₃ = [-0.5000,
1.0000]
Initial hidden state: h₀ = [0.0000, 0.0000] (hidden size 2)
Wxh = [[0.5000, -0.3000], [0.2000, 0.4000]], Whh = [[0.1000, 0.4000], [-0.2000, 0.3000]], bh =
[0.1000, -0.1000]
Why = [[0.6000, -0.3000], [0.2000, 0.5000]], by = [0.1000, 0.2000]

Step 1 — Compute h₁ (process the first input)
We need a1 = Wxh x1 + Whh h0 + bh. Since h0 = [0.0000, 0.0000], the recurrent term contributes nothing yet
— this is the very first step, so there is no history to bring forward.
Wxh x₁ = (0.5×1.0 + (−0.3)×0.5, 0.2×1.0 + 0.4×0.5) = (0.35, 0.40)

a₁ = (0.35, 0.40) + (0, 0) + (0.1, −0.1) = [0.4500, 0.3000]

h₁ = tanh([0.4500, 0.3000]) = [0.4219, 0.2913]

Why this step matters
tanh squashes each pre-activation into (−1, 1). Both components of a₁ were modest in size, so tanh has
not saturated — the gradient through this step will still be healthy (we revisit this idea in Section 2.7).

Step 2 — Compute h₂ (now the recurrence is active)
Wxh x₂ = (0.5×0.5 + (−0.3)×(−1.0), 0.2×0.5 + 0.4×(−1.0)) = (0.5500, −0.3000)

Whh h₁ = (0.1×0.4219 + 0.4×0.2913, −0.2×0.4219 + 0.3×0.2913) = (0.1587, 0.0030)

a₂ = (0.5500, −0.3000) + (0.1587, 0.0030) + (0.1, −0.1) = [0.8087, -0.3970]

h₂ = tanh([0.8087, -0.3970]) = [0.6689, -0.3774]

     •    Notice that h₂ depends on x₂ and on h₁ (which itself depended on x₁). This is exactly how the RNN
          carries information forward — h₂ already contains a trace of x₁.

Step 3 — Compute h₃
Wxh x₃ = (−0.5500, 0.3000),            Whh h₂ = (−0.0841, −0.2470)

a₃ = [-0.5341, -0.0470]         ⇒      h₃ = tanh([-0.5341, -0.0470]) = [-0.4885, -0.0470]

Step 4 — Produce the output y₃
y₃ = Why h₃ + by = [[0.6000, -0.3000], [0.2000, 0.5000]] × [-0.4885, -0.0470] + [0.1000, 0.2000] = [-0.1790,
0.0788]

     •    This is a many-to-one read-out: we only needed an output at the final time step (e.g. classifying
          the whole sequence). If a prediction were needed at every step, the same Why, by read-out
          would be applied to h₁ and h₂ as well.

2.4 Types of RNN Architectures
The recurrence itself never changes; what changes from application to application is simply where inputs
enter and where outputs are read out.




                  Figure 4. Five standard input/output wiring patterns built from the same recurrent cell.

     •    One-to-one — a single input maps to a single output; degenerates to a normal feedforward layer
          (rarely used with recurrence, shown for completeness).
     •    One-to-many — one input, a whole output sequence (e.g. image captioning: one image → a
          sentence).
     •    Many-to-one — a whole input sequence, one output (e.g. sentiment classification) — this is the
          pattern used in Worked Example 1 above.
     •    Many-to-many (aligned) — one output per input, same length (e.g. part-of-speech tagging).
     •    Many-to-many (encoder–decoder) — an encoder RNN compresses the input into a context
          vector; a separate decoder RNN generates the (possibly different-length) output sequence from
          it (e.g. machine translation).

2.5 Training an RNN: Backpropagation Through Time (BPTT)
     •    Idea: unroll the RNN for all T time steps (as in Figure 2), which turns it into one large feedforward
          computational graph — then apply ordinary backpropagation to that graph.
     •    Because the same weight matrix (say Whh) is reused at every time step, its total gradient is the
          sum of the gradient contributed at every time step:
                                              ∂L/∂Whh = Σₜ₌₁ᵀ ∂L/∂at ⊗ ht−1

     •    Each backward step from ht to ht−1 multiplies the incoming gradient by Whhᵀ and by the local tanh
          derivative — this repeated multiplication is the root cause of the vanishing/exploding gradient
          problem (Section 2.7).

                                                          h0.

2.6 Worked Example 2 — BPTT Gradient Computation
Given
Continue Worked Example 1. A target output target₃ = [1.0000, 0.0000] is supplied (one-hot encoding
for class 0), and the squared-error loss is applied at the final time step only (a many-to-one setup):

                 L = ½ ‖ y₃ − target₃ ‖² = ½ ‖ [-0.1790, 0.0788] − [1.0000, 0.0000] ‖² = 0.6981

Step 1 — Gradient at the output
∂L/∂y₃ = y₃ − target₃ = [-0.1790, 0.0788] − [1.0000, 0.0000] = [-1.1790, 0.0788]

     •    For squared error, ∂L/∂y = predicted − target — the gradient simply points from the prediction
          toward the target, scaled by the error.

Step 2 — Backprop into h₃ through the output layer
∂L/∂h₃ = Whyᵀ ∂L/∂y₃ = [[0.6000, -0.3000], [0.2000, 0.5000]]ᵀ × [-1.1790, 0.0788] = [-0.6916, 0.3931]

Step 3 — Backprop through tanh at t = 3
     •    The derivative of tanh is 1 − tanh²(a) = 1 − h², evaluated using the already-computed forward-
          pass value — this is why we saved every h_t during the forward pass.
∂L/∂a₃ = ∂L/∂h₃ ⊙ (1 − h₃²) = [-0.6916, 0.3931] ⊙ (1 − [-0.4885, -0.0470]²) = [-0.5266, 0.3922]




Dr. Manoj Kumar Sharma — Manipal University Jaipur                                                      Page 12 of 41
CCE3144 – Deep Learning                                                           Unit: Recurrent Neural Networks



Step 4 — Gradient contribution to Whh from t = 3
∂L/∂Whh |₃ = ∂L/∂a₃ ⊗ h₂ = [-0.5266, 0.3922] ⊗ [0.6689, -0.3774] = [[-0.3522, 0.1987], [0.2624, -
0.1480]]

     •    “⊗” here is an outer product: a gradient vector combined with the hidden state that was
          multiplied by Whh on the forward pass — this is the standard rule for the gradient of a matrix
          multiplication.

Step 5 — Propagate the gradient back one more step, to h₂
∂L/∂h₂ = Whhᵀ ∂L/∂a₃ = [[0.1000, 0.4000], [-0.2000, 0.3000]]ᵀ × [-0.5266, 0.3922] = [-0.1311, -0.0930]

∂L/∂a₂ = [-0.1311, -0.0930] ⊙ (1 − [0.6689, -0.3774]²) = [-0.0725, -0.0797]

∂L/∂Whh |₂ = [-0.0725, -0.0797] ⊗ [0.4219, 0.2913] = [[-0.0306, -0.0211], [-0.0336, -0.0232]]

Step 6 — Propagate back to h₁, then to h₀
∂L/∂h₁ = [[0.1000, 0.4000], [-0.2000, 0.3000]]ᵀ × [-0.0725, -0.0797] = [0.0087, -0.0529]           ⇒      ∂L/∂a₁ =
[0.0072, -0.0484]

∂L/∂Whh |₁ = [0.0072, -0.0484] ⊗ [0.0000, 0.0000] = [[0.0000, 0.0000], [0.0000, 0.0000]]

Why this term is zero
The contribution at t = 1 is multiplied by h₀ = (0, 0), the initial hidden state. With a zero initial state
there is nothing for the very first step to “multiply against” for this particular weight, so its contribution
vanishes.
This is a special case of using a zero initial state, not a general property of BPTT: the gradient signal
∂L/∂h₁ itself is still non-zero, so it correctly continues to update Wxh and bh through this step.

Step 7 — Total gradient (sum over all time steps)
                                 ∂L/∂Whh = ∂L/∂Whh|₁ + ∂L/∂Whh|₂ + ∂L/∂Whh|₃

[[0.0000, 0.0000], [0.0000, 0.0000]] + [[-0.0306, -0.0211], [-0.0336, -0.0232]] + [[-0.3522, 0.1987],
[0.2624, -0.1480]] = [[-0.3828, 0.1776], [0.2287, -0.1712]]

     •    The same mechanism (chain rule + outer product with the relevant input, summed across time)
          also gives ∂L/∂Wxh = [[0.2342, -0.4506], [-0.2844, 0.4478]] and ∂L/∂Why = [[0.5759, 0.0554], [-
          0.0385, -0.0037]]; these are left as Practice Question 32.

2.7 The Vanishing and Exploding Gradient Problem
     •    Look again at Steps 5–6 above: every step back multiplies the gradient by Whhᵀ and by a tanh-
          derivative factor that is always ≤ 1.
     •    Over T time steps this becomes roughly a product of T such factors — informally, gradient ∝ λᵀ,
          where λ reflects the typical size of Whhᵀ × tanh′.
     •    If λ < 1: the product shrinks exponentially with T — the vanishing gradient problem. Early time
          steps receive a near-zero learning signal, so the network effectively cannot learn long-range
          dependencies.




Dr. Manoj Kumar Sharma — Manipal University Jaipur                                                  Page 13 of 41
CCE3144 – Deep Learning                                                                    Unit: Recurrent Neural Networks



      •    If λ > 1: the product grows exponentially — the exploding gradient problem. Weight updates
           become huge and training diverges (loss becomes NaN / oscillates wildly).




  Figure 6. Relative gradient magnitude after k backward steps, for three illustrative values of λ. Even a modest λ = 0.5
                              leaves almost nothing after 10 steps; λ = 1.5 grows past 50×.

                      Table 2. Illustrative decay/growth of |λ^k| with the number of backward steps k.

          k (steps back)             λ = 0.5 (vanishing)          λ = 1.0 (stable)            λ = 1.5 (exploding)

Standard mitigations used in practice:

      •    Gradient clipping — rescale the gradient if its norm exceeds a threshold; a simple, effective fix
           for exploding gradients.
      •    Careful weight initialisation (e.g. orthogonal initialisation of Whh) — keeps λ close to 1 for
           longer.
      •    Truncated BPTT — limit how many steps gradients are propagated back through, trading long-
           range learning for stability/speed.
      •    Gated architectures — LSTM and GRU — redesign the recurrence itself so that gradients can
           flow across many steps largely unimpeded. This is the main solution used in practice, and is the
           subject of the next two sections.

3. Long Short-Term Memory (LSTM)

3.1 Motivation
     •    Plain RNNs struggle to learn long-range dependencies because gradients shrink (or blow up)
          exponentially as they are backpropagated through many time steps (Section 2.7).
     •    LSTM (Hochreiter & Schmidhuber, 1997) fixes this by giving the network a separate memory
          channel — the cell state — that information can flow along with only minor, mostly linear
          changes, instead of being repeatedly squashed through a matrix multiply and a tanh at every
          step.
     •    Three gates (small neural networks with sigmoid outputs in (0, 1)) learn when to write to, erase
          from, and read from this memory.

3.2 Architecture
     •    Cell state Ct — the long-term memory “conveyor belt” running along the top of the diagram
          below.
     •    Forget gate ft — decides what fraction of the old cell state to keep.
     •    Input gate it — decides how much of the new candidate information to write in.
     •    Candidate c̃t — the new content proposed for the cell state (not yet gated).
     •    Output gate ot — decides how much of the (updated) cell state to expose as the hidden state /
          output.

3.5 Why LSTM Solves the Vanishing Gradient Problem
     •    Recall from Section 2.7 that a plain RNN's gradient must pass through a matrix multiply by Whh
          and a tanh derivative at every single step — repeated many times, this shrinks (or explodes)
          exponentially.
     •    The LSTM cell-state recurrence is Ct = ft ⊙ Ct−1 + (new term) — this is additive, so ∂Ct/∂Ct−1 = ft
          (an element-wise scaling, not a matrix multiply followed by a squashing nonlinearity).
     •    If the forget gate learns to stay close to 1 for information that should be remembered, the
          gradient can flow backward through many time steps with almost no shrinkage — an unimpeded
          “gradient highway” along the cell state.
     •    This does not eliminate vanishing gradients entirely (very long sequences can still be difficult, and
          the hidden-state path through tanh still exists), but it dramatically extends how far back an RNN-
          family model can learn useful dependencies — this is the single biggest reason LSTMs outperform
          plain RNNs in practice.

3.6 Advantages and Limitations
     •    Advantages: learns long-range dependencies far better than a plain RNN; the gating mechanism
          is learned end-to-end from data; remains a strong, well-understood baseline for sequence tasks.
     •    Limitations: four sets of weights (forget, input, candidate, output) means roughly 4× the
          parameters of a plain RNN of the same hidden size (Section 6); inherently sequential computation
          makes it slower to train than fully parallel architectures such as Transformers; still not immune
          to very long sequences (hundreds/thousands of steps).

4. Gated Recurrent Unit (GRU)

4.1 Motivation
     •    Introduced by Cho et al. (2014), the GRU asks: can we get most of the benefit of LSTM's gating —
          protection against vanishing gradients, learned control over memory — with a simpler cell?
     •    GRU merges the forget and input gates into a single update gate, and removes the separate cell
          state entirely — the hidden state itself carries long-term memory.
     •    Fewer gates means fewer parameters (Section 6) and typically faster training, while remaining
          competitive with LSTM on many tasks.

4.2 Architecture
     •    Update gate zt — decides how much of the old hidden state to keep versus how much of the new
          candidate to mix in. It plays the combined role of LSTM's forget and input gates.
     •    Reset gate rt — decides how much of the past hidden state to use when forming the new
          candidate content.
     •    Candidate hidden state h̃t — a proposed new hidden-state value, computed using the reset
          (partially forgotten) past state.
     •    No separate cell state — ht itself is the blend of old and new content.

Significance of each equation:

     •    Update gate — close to 0 keeps the old state almost unchanged; close to 1 replaces it almost
          entirely with the new candidate.
     •    Reset gate — close to 0 makes the candidate ignore the past and depend mostly on the current
          input (useful when starting a new, unrelated chunk of a sequence, e.g. a new sentence).
     •    Final blend — a convex combination (weights sum to 1) of old state and new candidate. Like the
          LSTM cell-state update, this blend is dominated by simple arithmetic rather than repeated matrix
          multiplication, which is what protects the gradient.

4.5 GRU vs LSTM
     •    GRU has no output gate — the full hidden state is always exposed (LSTM can hide part of its cell
          state from the output via the output gate).
     •    GRU has no separate cell state — memory and output are the same vector, which simplifies the
          design but gives slightly less representational flexibility.
     •    GRU uses one combined update gate where LSTM uses two independent gates (forget, input) —
          fewer parameters, slightly less fine-grained control.
     •    In practice, the two perform comparably on many tasks; GRU is often preferred when training
          speed / parameter budget matters, LSTM when maximum modelling flexibility is preferred. Both
          comfortably outperform a plain RNN on long sequences.

5. Recurrent Neural Network Language Models

5.1 What Is a Language Model?
     •    A language model assigns a probability to sequences of words, or equivalently, predicts a
          probability distribution over the next word given all the words seen so far.
     •    Formally, for a sequence of words w1, …, wT, a language model estimates:
                     P(w₁, …, wᵀ) = P(w₁) · P(w₂ | w₁) · P(w₃ | w₁, w₂) · ⋯ · P(wᵀ | w₁, …, wᵀ₋₁)

     •    Language models power autocomplete, text generation, machine translation (as the decoder),
          speech recognition (choosing the most fluent transcription), and are the training objective
          behind today's large language models.

5.2 An RNN as a Language Model — Architecture
     •    Step 1 — Embedding: each word is converted from a discrete token into a dense vector (a row
          of a learned embedding matrix E).
     •    Step 2 — Recurrence: the embedding is fed into the RNN (or LSTM / GRU) exactly as in Sections
          2–4; the hidden state accumulates context from every word seen so far.
     •    Step 3 — Read-out: at every time step, the hidden state is projected to a vector of logits, one per
          vocabulary word, and passed through softmax to obtain a probability distribution over the next
          word.
     •    Training: at each step, the true next word is compared against the predicted distribution using
          cross-entropy loss; the same shared weights are updated via BPTT, exactly as in Section 2.5.

Significance:

     •    Embedding lookup turns a discrete word into a point in continuous space, where similar words
          can end up close together after training.
     •    Softmax converts raw logits into a valid probability distribution (non-negative, sums to 1) over
          the entire vocabulary.
     •    Cross-entropy loss penalises the model in proportion to how surprised it was by the true next
          word — a confident wrong prediction is penalised heavily; a confident correct prediction has
          almost no loss.

     •    Interpretation: a perplexity of 4.42 means the model is, on average, about as “confused” as if it

          practical worst case for a sensible model).

5.6 Beyond the Basics
     •    Teacher forcing — during training, the true previous word is fed as input at every step (as in
          Worked Example 5), even if the model's own previous prediction was wrong; this stabilises and
          speeds up training.
     •    Generation / sampling — at inference time there is no “true” next word, so the model's own
          output is fed back as the next input. Common strategies: greedy decoding (always pick the
          highest-probability word), sampling with temperature, and beam search.
     •    LSTM / GRU language models — in practice, the plain-RNN recurrence in this section is almost
          always replaced by an LSTM or GRU cell (Sections 3–4), since long documents need the improved
          long-range memory.
     •    Modern context — Transformer-based language models have largely superseded RNN-based
          ones for state-of-the-art results, but the evaluation concepts introduced here — next-word
          prediction, cross-entropy loss, and perplexity — remain exactly the same and are used to evaluate
          Transformer language models too.

Q1. Which of the following is NOT a defining property of sequential data? [1 mark]
     (A) Every sequence in the dataset must have exactly the same length. ✓ correct
     (B) The order of elements affects the meaning.
     (C) Later elements can depend on much earlier elements.
     (D) Elements are not statistically independent of their neighbours.
Answer: (A)
Solution:
Sequential data is explicitly allowed to be of variable length — sentences, audio clips and time series
routinely differ in length. This variability is precisely why ordinary feedforward networks (which need a
fixed-size input) struggle with sequences (Section 1.2), and why RNNs, which process one element at a
time and share weights across positions, are needed. Options B, C, and D all describe real properties of
sequential data (Section 1.1).

Q2. What is the single most important structural idea that lets an RNN process sequences of any length
using a fixed number of parameters? [1 mark]
     (A) Using convolutional filters that slide over the input.
     (B) Increasing the hidden size whenever the sequence is longer.
     (C) Sharing the same weight matrices across all time steps. ✓ correct
     (D) Training a separate small network for every time step.
Answer: (C)
Solution:
Because Wxh, Whh, Why (and their biases) are reused, identically, at every time step, the total number
of parameters does not grow with sequence length — a 5-word sentence and a 500-word document are
processed by exactly the same set of weights, applied repeatedly (Section 1.3, Section 2.1). Option D is
effectively the opposite of parameter sharing and would not generalise to unseen lengths.

Q3. In the standard update ht = tanh(Wxhxt + Whhht−1 + bh), every component of ht must lie in which
range? [1 mark]
     (A) (−1, 1) ✓ correct

Q4. If a pre-activation value a = 0, what are tanh(a) and its local derivative 1 − tanh²(a) at that point? [1

Q6. The vanishing gradient problem in plain RNNs is primarily caused by: [1 mark]
     (A) Using too few hidden units.
     (B) Using too large a learning rate.
     (C) The softmax function saturating.
     (D) Repeated multiplication by Whhᵀ and a tanh-derivative factor (≤ 1) at every backward step. ✓
     correct
Answer: (D)
Solution:
Backpropagating through T time steps multiplies the gradient by roughly T copies of Whhᵀ and a tanh-
derivative factor. If the typical size of this product (informally λ) is less than 1, the gradient shrinks
exponentially with T (Section 2.7, Figure 6). This has nothing to do with learning rate (B) or softmax (C),
and too few hidden units (A) is a capacity problem, not a gradient-flow problem.

Q16. List and briefly explain three properties that any model of sequential data must respect. [3 marks]
Solution:
     •    Variable length — sequences in a dataset are rarely all the same length (sentences, audio clips,

     •    Long-range dependencies — information at one position can affect the correct interpretation of

Q17. Give two distinct reasons why a plain feedforward network (MLP) with a flattened input vector is
a poor choice for variable-length text classification. [2 marks]
Solution:
     •    Fixed input size: an MLP requires a predetermined number of input features. Flattening text of
          different lengths into one vector either forces truncation/padding to an arbitrary maximum
          length, or simply cannot be done consistently.
     •    No parameter sharing across positions: if position 5 and position 50 of the flattened vector each
          get their own weights, the network must separately learn what a given word means at every
          possible position, wasting parameters and failing to generalise to lengths/positions not seen
          during training (Section 1.2).

Q24. Derive an expression for the Jacobian ∂ht/∂ht−1 of a plain RNN, and explain its role in BPTT. [4
marks]
Solution:
Step 1 — Write the recurrence: hₜ = tanh(aₜ), where aₜ = Wxh xₜ + Whh hₜ₋₁ + bh
Step 2 — Differentiate aₜ with respect to hₜ₋₁: ∂aₜ/∂hₜ₋₁ = Whh (the only term in aₜ that depends on hₜ₋₁)
Step 3 — Apply the chain rule through tanh: ∂hₜ/∂hₜ₋₁ = diag(1 − hₜ²) · Whh
     •    Here diag(1−hₜ²) is a diagonal matrix of the elementwise tanh-derivative values.

Role in BPTT
This single-step Jacobian is exactly the factor that gets multiplied in, once per time step, when the
gradient is propagated backward from hₜ to hₜ₋₁ (Steps 5–6 of Worked Example 2). Its repeated
application — diag(1−h²)·Whh chained T times — is precisely the mechanism behind the
vanishing/exploding gradient problem of Section 2.7: if the dominant eigenvalue of this product has
magnitude < 1, gradients vanish; if > 1, they explode.

Q25. Explain why the tanh derivative being maximised at a = 0 is relevant to the vanishing gradient
problem. [2 marks]
Solution:
     •    1 − tanh²(a) reaches its maximum value of 1 exactly at a = 0, and falls toward 0 as |a| grows (tanh
          saturates near ±1).
     •    Since each backward step through tanh multiplies the gradient by this factor, the best possible
          case at any single step is a multiplier of exactly 1 (no shrinkage) — it can never exceed 1. In
          practice, hidden units are rarely sitting at exactly a = 0, so the realistic per-step factor is usually
          noticeably below 1, which compounds multiplicatively over many time steps into the vanishing
          gradient problem (Section 2.7, and Q4 of Part A).

Q27. Explain the difference between the vanishing and exploding gradient problems in terms of the
quantity λ introduced in Section 2.7. [2 marks]
Solution:
     •    λ informally represents the typical magnitude of Whhᵀ combined with the local tanh-derivative
          factor, applied once per backward time step.
     •    If λ < 1, repeated multiplication across T steps produces λᵀ → 0 exponentially — the vanishing
          gradient problem; early time steps get almost no learning signal.
     •    If λ > 1, λᵀ grows exponentially — the exploding gradient problem; updates become huge and
          training destabilises. λ = 1 is the (unstable) knife-edge boundary between the two regimes.

Q29. List three standard mitigations for vanishing/exploding gradients in RNNs, and explain one of
them in detail. [3 marks]
Solution:
     •    Gradient clipping, careful (e.g. orthogonal) weight initialisation, truncated BPTT, and gated
          architectures (LSTM/GRU) are all standard mitigations (Section 2.7).
     •    Gradient clipping in detail: after computing the gradient for a batch, its norm ‖g‖ is compared
          against a threshold τ. If ‖g‖ > τ, the gradient is rescaled: g ← g × (τ/‖g‖), which preserves its
          direction but caps its magnitude. This is cheap to compute, requires no architecture change, and
          directly prevents the huge, destabilising updates caused by exploding gradients — though it does
          nothing to fix vanishing gradients.

Q34. Explain, using the forget-gate mechanism, why an LSTM can in principle remember information
for 100+ time steps, while a plain RNN struggles to. [3 marks]
Solution:
     •    If the forget gate learns a value close to 1 for a particular memory component, that component
          of the cell state is carried forward with almost no attenuation at every step: Ct = 1 × Ct−1 +
          (small/zero new term) ≈ Ct−1.
     •    Because this update is additive and element-wise (Section 3.5), the corresponding backward
          gradient ∂Ct/∂Ct−1 = ft ≈ 1 as well — so information (and its gradient) can survive many steps
          unchanged, in principle indefinitely.
     •    A plain RNN has no such mechanism: its hidden state is fully overwritten by tanh(…) at every step,
          and the corresponding gradient is repeatedly multiplied by Whhᵀ and a tanh-derivative < 1, which
          compounds toward zero (Section 2.7) — there is no learned way to “protect” a piece of
          information from this decay.

Q36. Why does LSTM keep the output gate separate from the cell-state update, instead of always

          should focus on a verb; the output gate lets the network learn when to reveal vs. withhold each
          memory component (Section 3.2).

Q37. If a particular LSTM memory unit has a forget gate consistently equal to 0.99 and an input gate of
0 (no new writes) for 100 consecutive steps, what fraction of the original value in that memory unit
remains? [2 marks]
Solution:
With it = 0, the update reduces to Ct = ft × Ct−1 at every step, so after 100 steps: C₁₀₀ = (0.99)¹⁰⁰ × C₀ =
0.366 × C₀.
     •    About 36.6% of the original value survives — a forget gate very close to 1 is needed to preserve
          information over long spans; even f = 0.99 loses almost two-thirds of the signal over 100 steps,
          showing why training must push ft very close to 1 for genuinely long-range memories.

Q39. In one line each, state the role of the reset gate and the update gate in a GRU cell. [2 marks]
Solution:
     •    Reset gate rt: decides how much of the previous hidden state to use when computing the new
          candidate content h̃ t.
     •    Update gate zt: decides the blend ratio between keeping the old hidden state and adopting the
          new candidate, ht = (1−zt)⊙ht−1 + zt⊙h̃ t.

Q41. Why does GRU not maintain a separate cell state, and what is the practical trade-off of this design
choice? [2 marks]
Solution:
     •    GRU's designers merged the memory and the exposed hidden state into a single vector, relying
          on the update gate alone to control how much of that single vector changes at each step — there
          is no second, separately-protected “conveyor belt” as in LSTM (Section 4.1–4.2).
     •    Trade-off: fewer parameters and a simpler cell (faster to train, Section 6), at the cost of slightly
          less representational flexibility — GRU cannot store a value in “private” memory while showing
          something different at the output, the way LSTM's output gate allows.

Q43. What does the GRU update reduce to when zt = 0 for all dimensions? What about when zt = 1? [2
marks]
Solution:
     •    zt = 0: ht = 1×ht−1 + 0×h̃ t = ht−1 — the hidden state is left completely unchanged; the new
          candidate is entirely ignored.
     •    zt = 1: ht = 0×ht−1 + 1×h̃ t = h̃ t — the old state is completely discarded and replaced by the new
          candidate.
     •    In practice zt learns intermediate values, blending the two continuously depending on the input.

Q44. Give an intuitive example of when a GRU's reset gate would be useful with a value close to 0. [2
marks]
Solution:
     •    Consider a document that is a list of unrelated short product reviews concatenated together. At
          the start of a new review, the content of the previous review is no longer relevant context for
          interpreting the new one.
     •    A reset gate close to 0 at that boundary lets the candidate h̃ t be computed almost entirely from
          the current input (ignoring the stale ht−1), effectively letting the network “start fresh” without
          needing to wait for the update gate to slowly overwrite the old state (Section 4.3).

Q45. Write the chain-rule factorisation of P(w₁, …, wᵀ) used by a language model, and explain in words
what each factor represents. [3 marks]
Solution:
                          P(w₁, …, wᵀ) = P(w₁) · P(w₂|w₁) · P(w₃|w₁,w₂) · ⋯ · P(wᵀ|w₁,…,wᵀ₋₁)

     •    This is simply the probability chain rule applied to a sequence: the joint probability of the whole
          sequence equals the product of each word's probability conditioned on every word before it.
     •    An RNN language model approximates every conditional factor P(wₜ | w₁,…,wₜ₋₁) with a single
          softmax output at step t, whose entire dependence on the (arbitrarily long) history w₁,…,wₜ₋₁ is
          compressed into the fixed-size hidden state hₜ₋₁ (Section 5.1–5.2).

Q48. Explain teacher forcing and describe one problem it can cause at inference (generation) time. [3
marks]
Solution:
     •    Teacher forcing: during training, the model is always fed the true previous word as input at each
          step, regardless of what the model itself would have predicted (Section 5.6).
     •    Problem — exposure bias: at generation time there is no ground truth to feed back in, so the
          model must feed in its own (possibly imperfect) previous prediction. Since the model never
          practised recovering from its own mistakes during training, small errors can compound as
          generation proceeds, leading to increasingly poor output quality — a mismatch between the
          training and inference conditions.

Q49. Give one application example each for plain RNN, LSTM, and GRU, and briefly justify each choice.
[3 marks]
Solution:
     •    Plain RNN: a short, fixed-pattern signal classifier (e.g. detecting a simple gesture from a few
          dozen accelerometer readings) — the sequences are short enough that vanishing gradients are
          not a serious concern, so the simplicity and speed of a plain RNN is an acceptable trade-off.
     •    LSTM: long-document sentiment analysis or long-range time-series forecasting (e.g. multi-week
          demand forecasting) — the long-range memory and fine-grained gating are worth the extra
          parameters when dependencies span long distances.
     •    GRU: on-device / mobile keyboard next-word prediction — a tight compute and memory budget
          favours GRU's roughly 25% parameter saving over LSTM, while still comfortably outperforming a
          plain RNN.

Q50. Summarise, in a short set of bullet points, the historical progression from RNN → LSTM → GRU →
Transformer, giving the main motivation behind each step. [4 marks]
Solution:
     •    RNN: introduced parameter sharing across time via a recurrent hidden state, solving the fixed-
          input-size and no-memory problems of feedforward networks (Section 1–2).
     •    → LSTM: added gated, additive memory (the cell state) specifically to fix the vanishing gradient
          problem that crippled plain RNNs on long sequences (Section 2.7 → Section 3).
     •    → GRU: simplified LSTM's gating (2 gates instead of 3, no separate cell state) to reduce
          parameters and training cost while keeping most of the long-range-memory benefit (Section 4).
     •    → Transformer (beyond this unit): replaced recurrence entirely with self-attention, allowing
          every position to directly attend to every other position. This removes the sequential step-by-
          step bottleneck (enabling full parallelisation across time during training) and provides a more
          direct path for gradients/information between distant positions than even LSTM/GRU can offer.
